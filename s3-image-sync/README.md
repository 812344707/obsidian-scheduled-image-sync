# 图床定时同步

复用开源插件 **S3 Image Sync 1.0.10** 的本地修正版。在 Obsidian 运行期间，按自定间隔扫描笔记中的本地图片，上传到自选的 S3 兼容服务，原位替换图片链接。

版本：`1.0.10-local.4`；插件 ID：`s3-image-sync-local`。这是本地修改版，不是上游官方发布版本。

## 安装

1. 解压安装包，将整个 `s3-image-sync-local` 文件夹复制到目标库的 `.obsidian/plugins/` 下。
2. 在 Obsidian「设置 → 第三方插件」中重新加载插件，启用 **图床定时同步**。
3. 打开插件设置，填写图床配置并测试连接，再开启「定期自动扫描全库」。首次安装默认不开启定时扫描。

升级时先停用插件，只覆盖 `main.js`、`manifest.json`、`styles.css`，并保留原有 `data.json`（图床配置与上传记录）。不要整文件夹替换而丢失数据；覆盖后重新启用。

本插件采用独立 ID，不会覆盖上游插件。同一库只启用一款执行自动上传的插件。

## 自定义图床

支持 阿里云 OSS、Cloudflare R2、AWS S3、MinIO，以及其他 **S3 兼容服务**。OSS 请选「阿里云 OSS」，按地域自动生成端点；其他兼容服务选「自定义 S3」后，可自行填写端点 URL、区域、存储桶、Access Key ID、Secret Access Key、图片公开访问 URL 和上传路径模板。

普通图床的「上传地址 + Token」接口与 S3 不同，本版尚未支持任意 HTTP 图床、PicGo 或 PicList。真实图床尚未配置和验证；本机测试服务成功不代表云端账号可用。凭据直接填在 Obsidian 设置中，会保存在本地插件目录的 `data.json`；安装包不含凭据。

## 定时设置

| 设置 | 用途 |
| --- | --- |
| 图片文件夹 | 填图片所在的库内路径，如 `attachments` 或 `附件`；扫描全库笔记，只上传此目录及子目录里的图片 |
| 定期自动扫描全库 | 开启或关闭定时处理 |
| 扫描间隔（分钟） | 可设 1 至 10080，例如 10、30、60；默认 30 |
| 跳过最近修改的文件（秒） | 默认 600；暂缓处理近期修改的笔记及图片，后续扫描再处理。测试时可设为 0 |
| 图片类型的「定时」选项 | 控制哪些图片扩展名加入定时扫描 |

开启后经过一个间隔才首次扫描。前一轮尚未结束时，不启动重叠扫描。定时功能仅在电脑上的 Obsidian 运行时工作；关闭应用或休眠期间不保证执行。手机端保留手动上传，尚未实机验证。

`![[附件/图片.png]]` 会变为 `![图片.png](https://你的访问域名/图片路径)`，图片继续显示在原处。已有笔记和以后新增的本地图片引用都可处理，已有远程图片链接跳过。此功能不追踪已经替换链接的原图后续修改，也不做双向同步。

定时扫描始终保留本地原图。上传失败或上传过程中笔记被编辑时保留原引用或用户的新内容，后续扫描再处理。若上传成功但写回冲突，已上传对象留在图床上，避免误删其他笔记共用的对象。

支持常见 Markdown 行内图片和 Obsidian 图片嵌入；HTML 图片、Markdown 引用式图片及复杂嵌套语法不保证识别。建议先用一篇测试笔记验证自己的图片格式。

## 未引用图片检索与清理

在插件设置中点击「检索图片」，或在命令面板执行「图床定时同步：检索未引用图片」。检索不上传、不删除文件，也不受上传目录和最小图片大小限制。

1. 扫描当前库全部本地图片，并读取 Markdown、Canvas、Bases 和 HTML，列出本地未引用图片及本插件记录中的未引用图床图片。
2. 按文件名或路径筛选，逐项勾选或全选本页；默认不勾选任何图片。
3. 选择「仅删除本地」或「本地＋图床删除」，预览具体路径和将删除的图床链接，再执行删除。
4. 结果逐项显示本地是否删除、图床已删除对象数以及失败或跳过原因。

「仅删除本地」将文件移入当前库的 `.trash` 回收站；不删除图床对象。「本地＋图床删除」先删除可核验的图床对象，成功后再处理本地文件。图床返回错误时保留本地图片；若图床成功、本地失败，会分别报告结果。已删除本地但还保留图床的上传记录可在后续检索中继续清理。

本地图片没有引用，不等于图床图片没有引用：上传后留下的本地副本可以单独删除；图床链接仍被笔记使用时，禁止连图床一起删。同一图床对象被多张本地图共享时也检查对象引用。删除前重新读取文档、核对文件内容和图床配置，任务间防止并发上传与清理。

为避免误删，正文提及、代码示例、普通图片文件链接和不明确的同名引用也算保留依据。因此列表是可清理候选，不是认定所有未显示的图片都无效。不扫描其他库、第三方网站、隐藏配置目录或不支持的二进制文档，不能确认这些位置是否使用图片；共享图床应自行核对外部使用情况。

从 `.3` 版开始持久保存源文件、内容哈希、端点、存储桶、对象键和访问链接，不额外保存凭据。图床删除只使用这些上传记录，不遍历整个存储桶、不根据旧日志或文件名猜测对象。旧版图片或其他插件上传的图片若缺少记录，只支持本地删除。切换过图床后，应恢复记录对应的端点、存储桶、区域及可用凭据再删除远端对象。

图床删除无法通过本插件撤销，实际恢复能力取决于服务商版本控制和备份。检索和清理均需手动发起，不会按定时上传计划自动删除。

## 本地修正

- 保存并恢复扫描开关、间隔、图片目录等设置。
- 定时扫描保留原图，取消上游强制延迟删除行为。
- 按引用位置替换，避免连带改写代码示例；普通文件链接保持链接形式。
- 防止定时扫描重叠及同一笔记的并发上传；写回前检查笔记是否改变。
- 写回失败时不删除可能被其他笔记引用的远程图片。
- 修正独立设置窗口中上传路径说明显示为 `[object DocumentFragment]` 的问题。

## 阿里云 OSS（1.0.10-local.4 新增）

服务商选择「阿里云 OSS」，填写地域（如 `cn-hangzhou`）、Bucket、RAM AccessKey ID/Secret 和公开访问 URL。端点按地域自动生成，无需填写，也无需 PicGo。详细步骤见 [阿里云配置教程](../docs/aliyun-oss-setup.md)；ZIP 内附 `aliyun-oss-setup.md`。

本版使用 OSS 外网 S3 兼容接口和虚拟托管寻址；不会修改 Bucket/Object 权限。公开图片链接需要匿名读取权限。连接测试只验证列举权限；上传、公开显示和删除要分别用样例验证。真实 OSS 账号、手机端尚未联调。

同时修复中文及特殊字符路径的重复编码、权限错误反复重试、连接测试误把重定向视为成功的问题。新增寻址方式记录，旧记录按原有路径方式保留，切换服务商不会把旧记录误当作 OSS 对象删除。
